# Требования продукта

## Основные правила

| ID | Требование | Приёмка |
| --- | --- | --- |
| R01 | Пользователь выбирает дату и услугу, не время | В форме и API нет пользовательского appointment_time |
| R02 | 100 мест на office/date | Все услуги и окна расходуют один бюджет, 101-я запись отклоняется |
| R03 | Один паспорт — одно посещение на дату | Новый аккаунт и другой офис не обходят запрет |
| R04 | Фото до бронирования | Нельзя подтвердить обычную запись без успешного doc-check или журналируемого решения сотрудника |
| R05 | OCR не объявляет подлинность | В ответах нет authenticity_verified=true по результату фото |
| R06 | Проверка оригинала у окна | Начать обычный приём можно только после отметки сверки |
| R07 | Один сопровождающий | companion_count только 0 или 1; собственного приёма по талону нет |
| R08 | Номер назначается при подтверждении | Порядок монотонный внутри office/date/service; отменённые номера не повторяются |
| R09 | Талон не передаётся | Нет публичной операции изменения document_id в записи |
| R10 | Отмена освобождает, завершение не освобождает | Счётчик отражает и занятые, и использованные места |
| R11 | Нет проверки на входе | Нет роли входного контролёра и обязательного check-in |
| R12 | Публичное табло без персональных данных | Только номера, окна, состояние работы и версия очереди |

Часовой пояс: `Europe/Podgorica`; datetime хранения — UTC, business_date — локальная дата. Нельзя считать дату по часовому поясу браузера.

## Путь заявителя

Телефон → код → фото → распознанные данные → исправление/подтверждение → выбор услуги и дня → проверка лимитов → именной талон → отслеживание → вызов → оригинал у окна → результат.

Отдельные ветки: плохое фото, сомнение OCR, полный день, лист ожидания, конфликт паспорта, отмена, перенос, пропущенный вызов, прекращение приёма.

## Путь сотрудника

Вход → закрепление за окном/услугами → следующий талон → сверка оригинала → начать → завершить. Дополнительно: повторить вызов, пропустить, вернуть пропущенного по регламенту, неявка, расхождение, закрытие дня. У всех ручных исключений actor/reason/time.

## Качество

Работа на мобильном экране 360 px и настольном; понятное восстановление после перезагрузки. Прототип обновляет очередь polling каждые 5 секунд; это не обещание доставки SMS. Показ ожидания опционален и появляется только при достаточной статистике; не выдавать точное время приёма.

## Технические значения по умолчанию

Временные параметры в `docs/DECISIONS.md` — конфигурация прототипа, а не согласованный регламент MUP. Codex не должен спрашивать о них перед каждой задачей. Для реального пилота открытые вопросы закрываются отдельно.
