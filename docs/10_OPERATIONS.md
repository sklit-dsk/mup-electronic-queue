# Локальная работа и подготовка пилота

> Обновление: Compose и Dockerfiles реализованы. Фактическая команда запуска и проверки — в README.md; в этой среде Docker не запускался.

## До реализации

Docker Compose уже создан; см. актуальную инструкцию в README. Сначала Git, VS Code/Codex и документация. Выбрать один вариант окружения: Windows с Docker Desktop и доступным Compose либо WSL2, если так удобнее работать. Не смешивать Windows node_modules и Linux node_modules.

## Контракт команд, которые должен создать T00

| Команда после T00 | Назначение |
| --- | --- |
| `docker compose up --build` | Локальные api/web/db/worker; demo mode, loopback |
| `docker compose run --rm api uv run pytest` | Backend checks; до T01 только доступные smoke/unit |
| `docker compose run --rm api uv run ruff check .` | Python lint |
| `docker compose run --rm web npm run check` | TypeScript + frontend lint |
| `docker compose run --rm web npm run build` | Frontend build |
| `docker compose run --rm api uv run alembic upgrade head` | После T01: миграции |

Это целевые команды, не утверждение о текущей работоспособности. T00 обязан проверить их для созданного scaffold; дальнейшие задачи расширяют тестовый набор. E2E-команду T05/T12 фиксируют после появления окружения браузера.

В Compose нет автоматического `down -v` или удаления чужих volumes. Сервисы проекта имеют собственные имена/порты/БД. Миграции запускаются отдельно, до нескольких api/worker процессов, не одновременно в каждом контейнере.

## Конфигурация

Разделить demo/staging/pilot. `.env.example` — шаблон контракта, не готовые секреты. `.env` не коммитится. Приложение проверяет обязательные ключи, выбранных провайдеров, время и retention. Pilot с demo-провайдерами должен завершаться ошибкой при старте.

## Worker

Имеет healthcheck, graceful shutdown, lease для задания, bounded retries и журнал безопасных ошибок. OCR, outbox, offers и удаления должны восстанавливаться после restart. Нет обещания exactly-once SMS: доставка at-least-once с dedupe, доменные операции идемпотентны.

## Резервирование и сбои

Отдельные backups БД и закрытого файлового хранилища плюс сохранение необходимых ключей в другом защищённом месте. Проверить восстановление на чистой тестовой среде. При отказе SMS талон остаётся действительным и виден в кабинете. При отказе БД не выдавать локальные фиктивные талоны.

Для пилота согласовать работу при полном отказе системы: кто фиксирует остаток очереди, кто возобновляет обслуживание и как сверяет ручные действия после восстановления. Восстановление из backup не должно незаметно вернуть выданные места в FREE.

## Стенд и публикация

Сначала закрытый стенд на синтетических данных. Homelab допустим для разработки; использование его для реальных паспортов не считается автоматически утверждённым решением. HTTPS, область доступа сотрудников, хранение файлов, SMS-провайдер и работа MUP согласуются до реального пилота. Публикация не входит в T00 и не происходит от одного факта наличия домена.
