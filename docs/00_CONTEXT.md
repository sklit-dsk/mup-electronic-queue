# Контекст и границы

Инициатор: Danila Sklovskii, Подгорица. Нужен проект для самостоятельной реализации через Codex в VS Code. Основа — обсуждение и `MUP_Electronic_Queue_Concept_RU.pdf`, итоговая версия 2.0 от 15.10.2026. Текстовые спецификации этого набора уточняют её для разработки.

Проблема: физическая очередь и случаи, когда посредник занимает место, а затем приводит группу клиентов. Решение закрепляет обслуживание за заявителем, оставляет одного сопровождающего и показывает продвижение очереди онлайн.

Запись не имеет назначенного часа. Приём пилота 08:00–14:00, до 100 мест на отделение в день. Оценка 100–150 фактических посещений от инициатора не является измеренной нагрузочной характеристикой.

## Первая версия

Один пилотный офис, одна услуга, несколько обслуживающих окон; в модели предусмотрены office_id и service_id. Есть кабинет, фото паспорта, OCR, накопительная база, запись/отмена/перенос, очередь, проверка у окна, табло, лист ожидания и журнал.

Сначала строим работающий процесс с синтетическими документами. Затем реальный адаптер OCR и поставщик SMS. При демонстрации явно показываем режим DEMO и неподключённые интеграции.

## За пределами первой версии

Электронная подача на ВНЖ; доступ к госреестрам; доказательство подлинности по фото; биометрия/селфи/liveness/NFC; платежи; кабинет агентства для массовой записи; мобильные приложения; автоматические юридические решения.

Дети и законные представители требуют отдельного процесса до их включения в реальный пилот. Не считать неподдержанный случай попыткой мошенничества.

## Предел результата

Это не действующая официальная система MUP. Сайт без согласованного использования сотрудниками не управляет реальным порядком приёма. Очередь организует нагрузку, но не увеличивает число обработанных дел сама по себе.
