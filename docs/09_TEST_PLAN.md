## Как тестировать конкурентность

Дополнение 2а (tests/test_episodes.py): неизменность первичного приёма/вместимости/дневного запрета; роли/причины/scope; одна активная попытка повтора; новый оригинал обязателен; версии/идемпотентность; два вызова и возврат; неявка/отмена/отказ без освобождения использованного места; конец дня и исторический остаток; безопасное табло; конкурентное создание и гонка repeat/call-next одного окна. Browser E2E подтверждает историю обоих приёмов, неизменную вместимость и 390 px. Миграция существующей 0002 проверена отдельно, включая безопасный отказ downgrade при непустой истории.

Дополнение 2б (tests/test_document_access.py): конфликт чужого фото; recovery талоны/waiting/outbox и отзыв сессий; REPLACE с history/document_revision; неизменность ACTIVE/SPENT claims и seats; scope/IDOR; expired/stale/cancelled requests; обязательность трёх проверок; IN_SERVICE; held waitlist; leases; stale ORM cache; параллельные решения и гонка confirm/replace. Migration drill проверяет backfill 0003→0004, пустой downgrade/re-upgrade и отказ удаления истории. Browser E2E проходит весь UI замены; 16.10.2026 все 4 сценария прошли на отдельной чистой серверной БД в официальном Playwright Chromium container.

Добавлено в этапе 1: границы 07:59/08:00/13:59/14:00 Europe/Podgorica; start после закрытия запрещён, complete начатого разрешён; два вызова и обе паузы; возврат со сбросом сверки; исторический остаток; причины/права/идемпотентность ручного закрытия и переноса; сохранение владельца; полный целевой день; приоритет листа ожидания; гонка call-next/close. Тесты: tests/test_workday.py. Браузер: обычный приём и закрытие/перенос, 390 px. Миграция 0001→0002 и откат/повтор проверены отдельно на синтетических CALLED/BOOKED/COMPLETED.

Настоящий PostgreSQL, отдельный Session/соединение на запрос. Barrier для синхронного старта. Проверять итог БД: seats, claims, active window assignment, номера и outbox, а не только HTTP-коды. Тест не должен сериализоваться общим lock в test-клиенте. Для тестов создать отдельную БД, не использовать data volume рабочего окружения.

## Уровни

- Unit: переходы состояний, normalizer, MRZ check digits, политики отмены и времени.
- Integration: БД, миграции, конкуренция, авторизация, outbox/leases.
- E2E: вход → документ → запись → вызов → оригинал → завершение; полный день/ожидание; отмена/перенос; права applicant/staff.
- OCR evaluation: измерять распознавание полей отдельно от аутентичности. Только синтетические/разрешённые данные.

Не писать тесты, которые просто повторяют implementation detail. После изменения документации проверять ссылки и согласованность. После domain-change выполнять связанные integration checks. В T12 запускается полный установленный набор; сохранять точные команды и результаты в STATUS, а не выдуманные «все тесты прошли».
