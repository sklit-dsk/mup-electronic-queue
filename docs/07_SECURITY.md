# Доступ и защита данных

## Три режима

| Режим | Данные | Провайдеры |
| --- | --- | --- |
| demo/test | Только синтетические | Fake SMS/OCR, явный DEMO banner |
| staging | Синтетические, пока отдельно не разрешён иной набор | Настроенные адаптеры, без публичной записи реальных людей |
| pilot | Реальные после согласования | Реальный OTP, рабочий OCR/разбор, настроенное хранение |

Pilot не запускается с FakeDocumentReader, TestSmsProvider, пустыми ключами, default staff password или неуказанной retention-политикой. Проверка делается на startup, а не одной надписью в README.

## Авторизация

Applicant видит только свои объекты. Staff имеет office/service scope; supervisor — отдельные исключения; admin — настройки и аудит. Роль выдаётся серверным административным процессом. Запретить IDOR для upload/check/document/ticket/offer и выдачи изображений. Просмотр фото журналируется без содержимого.

Не создавать анонимный endpoint «покажи, кто владеет паспортом». Конфликт реквизитов даёт нейтральное сообщение и путь разбора. Загрузка чужого фото не меняет подтверждённый профиль. Доступ к фото через авторизованный endpoint с Cache-Control: no-store; object key не равен номеру паспорта.

Recovery/REPLACE решает только admin того же office после трёх явно отмеченных очных проверок и причины. Requester получает лишь собственный безопасный статус, без прежнего owner/document/reason. Recovery отзывает все сессии прежнего аккаунта; уже начавшаяся операция прежнего владельца после блокировки повторно проверяет owner. Связанный outbox блокирует recovery при активной доставке, затем переводится новому владельцу; неоднозначные старые события отменяются. Audit/outbox не содержат сырые паспортные поля.

## Аутентификация

OTP короткоживущий, одноразовый, ограничен по попыткам, номеру и IP; хранить только защищённое представление. Не выводить действующий OTP в ответе/логах. Для тестового провайдера отдельный inbox с искусственными контактами, только loopback и demo/test; он недоступен в pilot. Staff-секреты задаются при создании, пароль хранится сильным password hash, recovery не через публичное назначение роли.

## Загрузки

Проверять сигнатуру/декодирование, MIME, размер, пиксели; запретить SVG/HTML, path traversal, decompression bomb и выполнение файлов. Сгенерировать своё имя, strip metadata при подготовке рабочей копии; сырой EXIF не нужен для проверки. Входящая картинка и OCR-текст не могут управлять системными инструкциями, SQL или переходами талона.

## Хранение

Паспортные реквизиты шифруются, lookup fingerprint — keyed HMAC, ключи вне репозитория и дампа БД. Cookie не хранить в localStorage. Без фото/ФИО/номеров в публичных DTO, метриках, trace, ошибках и аналитике. Отдельно шифруемые backups, доступ к ключам не объединять с публичной выдачей файлов.

Для реального пилота значения retention должны быть явно утверждены. Для demo: фото 24 часа, синтетические учётные данные до очистки стенда. Удаление фото выполняется повторяемым worker job, очищает также временные копии; backup-retention и удаление реквизитов описываются отдельно. Не обещать мгновенное удаление из всех backups.

## Угрозы, которые проверяем

Массовые аккаунты, повторные паспортные данные, 101-я запись, гонки переносов/вызовов, отмена-передача, захват чужого профиля, утечка фото, staff без scope и поддельные изображения. CAPTCHA/IP — дополнительная защита. Без идентификации владельца нельзя гарантировать, что посредник не записывает реальных клиентов; это известная граница.
