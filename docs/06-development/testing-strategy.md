# Стратегия тестирования (черновик)

## Приоритетные проверки
- BR-001: 100 успешных заявок, 101-я отклоняется.
- Одновременные регистрации не переполняют лимит.
- Повторная отправка одного запроса не создаёт две записи.
- BR-002: нет временных слотов ни в форме, ни в серверной схеме.
- BR-003: оператор может проверять запись только со своими правами.
- Пользователь не видит чужие записи.
- Нет утечек персональных данных в логах, ошибках и демонстрации.

## Уровни
Unit: бизнес-правила. Integration: транзакции БД и API. E2E: посетитель и оператор. Security: RBAC и защита данных. Accessibility: мобильность и понятность сообщений.

Автоматизация: Python/pytest + Playwright — предложение, а не утверждённый стек.
