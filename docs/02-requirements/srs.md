# SRS — Спецификация требований

**Версия:** 0.1 · **Дата:** 2026-10-15 · **Статус:** рабочий проект, не подтвержден MUP.

## 1. Назначение
Предварительная электронная очередь для подачи обращений иностранцев в MUP Черногории. Окончательная предметная область (ВНЖ или шире) подлежит уточнению.

## 2. Согласованная концепция
- **FR-001** Посетитель выбирает доступную дату записи без временного слота.
- **FR-002** Система ограничивает число успешных электронных регистраций 100 на одну дату.
- **FR-003** Посетитель получает подтверждение регистрации/идентификатор (формат требует решения).
- **FR-004** Сотрудник проверяет действительность регистрации непосредственно у окна.
- **BR-001—004** См. [бизнес-правила](business-rules.md).

## 3. Предлагаемые функции (не согласованы)
- **FR-P01** Администратор управляет календарём доступных дат и дневным лимитом.
- **FR-P02** Оператор находит запись по подтверждению и изменяет статус обслуживания.
- **FR-P03** Система предотвращает дубликаты по утверждённым критериям.
- **FR-P04** Система протоколирует действия сотрудников без избыточных персональных сведений.
- **FR-P05** Посетителю доступен просмотр статуса записи.

## 4. Нефункциональные требования (предложения)
- **NFR-P01** Контроль доступа на основе ролей (RBAC), отдельные учётные записи операторов.
- **NFR-P02** Шифрование TLS для передачи данных, управление ключами и секретами отдельно от репозитория.
- **NFR-P03** Защита от массовых автоматических регистраций с учетом доступности и приватности.
- **NFR-P04** Атомарная проверка дневного лимита, защита от повторной отправки запросов.
- **NFR-P05** Логирование и минимизация личных данных, политики хранения/удаления.
- **NFR-P06** Доступность интерфейса на мобильных устройствах, понятные ошибки; язык интерфейса согласовать.

## 5. Сценарии
1. Посетитель выбирает дату, вводит минимальный набор согласованных полей и подтверждает.
2. Сервер атомарно проверяет лимит и выдаёт запись либо сообщает об отсутствии мест.
3. У окна сотрудник проверяет подтверждение и идентичность по утвержденной процедуре.

## 6. За пределами MVP
Загрузка фотографий паспортов, OCR и ИИ для проверки документа — перспективная опция, **не** средство надёжного подтверждения подлинности документа. Требуются отдельная оценка необходимости, законности, хранения, ошибок/смещений модели и право человека на проверку.

## 7. Ограничения и вопросы
Реальные правила МУП, юридическая база обработки персональных данных, взаимодействие с существующей живой очередью, аннулирование, отсутствие посетителя и правила выдачи номеров не определены. [Реестр вопросов](open-questions.md).

## 8. Критерии приемки первой версии (проект)
- Невозможно получить 101-ю активную запись на одну дату при одновременных запросах.
- Нет выбора времени в интерфейсе и API регистрации.
- Оператор способен найти запись у окна при наличии полномочий.
- Никаких реальных паспортов в тестовых средах/демо.
- Ошибки и недоступные даты обрабатываются явно.
