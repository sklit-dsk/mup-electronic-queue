# Как работать с Codex в VS Code

> Обновление: первый scaffold уже существует. Начинай с STATUS.md и IMPLEMENTATION.md, затем выбранной незавершённой части задачи.

## Как подгружаются инструкции

Корневой `AGENTS.md` содержит постоянные правила. Вложенные AGENTS.md уточняют области, но нельзя считать, что Codex автоматически прочитал каждую вложенную папку. Перед backend/frontend-задачей промпт явно поручает открыть соответствующий файл. Остальные `.md` — спецификации, их чтение задаётся ссылками и инструкциями, а не магией названия.

Проектный AGENTS.md не отменяет глобальные правила твоего Codex. Не копируй этот файл в глобальную папку Codex. Если инструкции добавились после начала сеанса, начни новый разговор и попроси перечислить прочитанные источники. Официальный механизм описан в SOURCES.

## Один цикл

1. Открой папку проекта и проверь Git changes.
2. Возьми следующую задачу из ROADMAP, зависимости которой DONE.
3. Отправь её промпт. Codex кратко планирует, реализует и проверяет её.
4. Посмотри diff, запусти указанные команды, проверь UI, если задача меняет интерфейс.
5. Попроси ревью по `prompts/04_REVIEW.md`, исправь обнаруженное в рамках текущей задачи.
6. Зафиксируй проверенный этап в git, когда считаешь его готовым. Новый чат — по `prompts/03_RESUME.md`.

Не проси «сделай всё по этим файлам», если хочешь проверять этапы. Это поручение охватит весь проект. Для обычной работы используй одну задачу. Не требуются 10 отдельных ролей агентов или свои skills: AGENTS, спецификации, STATUS и task-файлы достаточны.

## Универсальный запрос

```text
Прочитай AGENTS.md, STATUS.md, ROADMAP.md и tasks/TXX_имя.md.
Прочитай указанные в задаче спецификации и вложенный AGENTS.md нужной области.
Проверь текущий код и git status. Выполни только TXX до её критериев готовности.
Сначала покажи короткий план. Затем реализуй, запусти проверки и исправь ошибки.
Обнови STATUS.md и состояние задачи; не помечай непроверенное как готовое.
В конце дай точные команды проверки и ограничения. Не переходи к следующей задаче.
```

Здесь TXX нужно заменить реальным ID/именем из ROADMAP. Первый промпт уже заполнен и лежит в `prompts/01_START.md`.

## Если проверка не запускается

Codex фиксирует команду, причину и что нужно установить. «Не запускал» не равно PASS. Если нет Docker/БД, он не заменяет PostgreSQL-тесты SQLite и не снимает требования конкурентности. Возвращаемся к той же задаче после устранения проблемы.

## Как менять идею

Перед реализацией нового поведения попроси обновить PRD, DOMAIN, затронутый API, DECISIONS и тест-критерии. Код и документация должны описывать одну версию. Реализацию следующего этапа начинай после проверки текущего.
