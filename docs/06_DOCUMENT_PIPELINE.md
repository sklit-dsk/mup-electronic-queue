# Фото, OCR и MRZ

## Конвейер

Upload → проверка реального формата/размера → приватное хранение → quality check → OCR → MRZ parsing → deterministic validation → сравнение полей → подтверждение пользователем → привязка версии документа к doc-check → право бронирования.

Только JPEG/PNG в первом прототипе, до 10 MiB и 20 мегапикселей после декодирования. HEIC/PDF не принимаются молча: показать понятное сообщение и возможность переснять. Порог качества настраивается по тестам, а не выдуманному проценту достоверности.

## Состояния проверки

PENDING → PROCESSING → PASSED / RETAKE / REVIEW_REQUIRED / FAILED. FAILED — техническая ошибка с возможностью повтора. PASSED означает согласованность прочитанных данных, а не аутентичность документа. Ручной разбор создаёт отдельное событие и обоснование.

Записывать parsed fields, issues, engine version и confidence по полям только если движок это действительно предоставляет. Нет поля с ложным обещанием `passport_is_real=true`.

## Извлекаемые поля

Страна выдачи, тип, номер/серия при наличии, ФИО, дата рождения, дата окончания, MRZ. Проверить страну и формат, правдоподобие дат, срок действия, контрольные цифры MRZ и согласованность видимой зоны. Нельзя считать отсутствие MRZ признаком подделки для всех документов. Первым поддержанным форматом делаем TD3; остальные форматы отправляются на разбор, а не автоматически отклоняются как поддельные.

Исправление ключевых полей пользователем запускает повторную сверку: нельзя поменять номер после PASSED и бронировать по старому результату. Не заменять произвольно O/0, I/1 и латиницу/кириллицу в номере.

## Порядок реализации

1. FakeDocumentReader на синтетических fixtures: стабильные сценарии, включается только в demo/test. Он не анализирует настоящее фото и так и обозначается.
2. Реальный локальный OCR adapter. Tesseract можно рассмотреть как исходный кандидат; фактическую пригодность выбранного движка подтвердить отдельным небольшим набором синтетических или разрешённых тестовых изображений. Выбор фиксируется в DECISIONS.
3. MRZ parser/контрольные цифры и сравнение видимых полей, отдельные от OCR. Не позволять модели менять правила лимитов.
4. Специализированная проверка признаков подделки — отдельное расширение после измерений; не обещание MVP.

Интерфейс DocumentReader возвращает данные, ошибки и диагностические признаки, не доступ к БД и не право выдать талон. Сетевой LLM не обязателен. Внешняя отправка паспортов не включается по умолчанию; выбор внешнего обработчика требует отдельного решения владельца проекта.

## Проблемы и обходы

Фото настоящего паспорта не доказывает присутствие владельца. Синтетическое изображение может пройти OCR/MRZ. Общий ИИ не гарантирует выявление монтажа. Поэтому у окна остаётся проверка оригинала; подтверждение у окна не отменяется для повторного посещения.

Не сохранять реальные документы в git или CI. Синтетические изображения явно помечать как TEST / NOT A VALID DOCUMENT. Для оценки OCR использовать accuracy по полям, долю RETAKE/REVIEW_REQUIRED и распределение времени обработки. Не публиковать «точность проверки подлинности» по результатам распознавания текста.
