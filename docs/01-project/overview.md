# Обзор проекта

**Название:** MUP Electronic Queue. **Статус:** концепция/MVP, неофициальная инициатива.

## Проблема
Приём без прозрачного планирования создаёт неопределённость для посетителей и нагрузку на сотрудников. Фактические метрики необходимо собрать до пилота.

## Цель
Проверить возможность удобной дневной электронной регистрации и обслуживания по очереди с минимальным изменением работы окон.

## Первая версия
- запись на дату, не на определённое время;
- проектный лимит 100 электронных заявок в день;
- проверка сотрудником непосредственно у окна;
- администрирование регистраций и доступных дат — предлагаемый функционал, детали согласовать.

## Вне MVP
Распознавание подлинности паспорта и ИИ-проверка не утверждены. Нет интеграции с государственными базами без официального согласования.

## Участники
Посетитель, оператор окна, администратор системы; государственное учреждение — потенциальный партнёр, но не подтверждённый заказчик.

## Критерии успеха (предложение)
Процент успешно завершённых регистраций, время обработки у окна, количество дублей/пропусков, доступность сервиса, оценка удобства пользователей.
