Для любого изменения: дата, проблема, выбранное поведение, альтернативы при необходимости, последствия, файлы и тесты. Не хранить здесь журнал каждого форматирования.

16.10.2026, D18: три отдельные сборки не создаются, чтобы не дублировать дизайн, типы и API-клиент. Разделение выполняется маршрутом, навигацией и экраном входа; сессия с неподходящей ролью не открывает интерфейс другого портала. Это не security boundary само по себе: окончательный запрет выполняют `staff()`/`admin()` и object scope на сервере. Свободный выбор любой роли сохранён только через явно обозначенный `/demo` при APP_ENV=demo и отсутствует в pilot.

16.10.2026, 2б: пользовательская загрузка создаёт только запрос. Admin обязан зафиксировать проверку оригинала, доступа к аккаунту и принадлежности одному человеку. Recovery меняет владельца канонической записи и её связанных объектов, но не переносит прочие документы аккаунта. Replacement добавляет ревизию того же document_id; tickets сохраняют номер ревизии на момент записи, а старые fingerprints остаются уникальными aliases. Уже существующие разные document_id не объединяются автоматически: это могло бы смешать людей и лимиты. Миграция 0004 запрещает downgrade после появления запросов/изменений.

15.10.2026, 2а: отдельная сущность повторного приёма выбрана для сохранения первого результата/времени без отката первичного талона в CALLED. Весь повтор происходит в исходный местный день, открывается admin с причиной и сразу занимает свободное окно как журналируемое исключение. Все новые пути вызова/возврата используют OfficeDay lock и проверяют оба типа приёмов. Primary Ticket.version меняется для revision/polling, остальные поля первого приёма сохраняются. В 0003 нет backfill фиктивных эпизодов для старых записей; downgrade с историей останавливается. Это default прототипа, требующий регламента MUP перед пилотом.

15.10.2026, этап 1: D10 реализован как два вызова с паузой 120 секунд после каждого. Возврат SKIPPED идёт через BOOKED с прежним номером и новым циклом вызовов; очная сверка сбрасывается. Это default прототипа, не утверждённый регламент MUP. Новый приём блокируется после 14:00; начатый завершается. Остаток не становится неявкой автоматически. Для переноса остатка пока применяется обычная очередь целевого дня с приоритетом существующего листа ожидания. Изменения: domain/main/models, миграция 0002, staff UI; проверки в test_workday.py и e2e/queue.spec.ts.
