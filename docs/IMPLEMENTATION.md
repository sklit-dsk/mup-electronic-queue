# Фактическая реализация v0.1

Дата: 16.10.2026. Этот файл отличает код от исходного плана. Для текущего API/схемы он имеет приоритет перед набросками DATA_MODEL/API_CONTRACT. PRD и DOMAIN задают бизнес-правила; непокрытые расширения перечислены отдельно.

## Реализованные компоненты

16.10.2026: одна React-сборка разделена на независимые порталы по URL. `/` показывает только applicant-навигацию, `/staff` — очередь и рабочее окно, `/admin` — служебную работу и управление, `/demo` — явный каталог синтетической демонстрации. Несовместимая с маршрутом сессия не получает чужой интерфейс. Это UX-разделение дополняет, но не заменяет серверный RBAC: endpoints staff/admin по-прежнему проверяют роль и scope. В APP_ENV=demo целевые demo-входы остаются доступны для презентации; в pilot endpoint `/auth/demo` возвращает 404.

Этап 2б: document_revisions/document_requests и миграция 0004. Восстановление доступа и замена паспорта проходят через admin своего отделения с причиной и отдельными отметками очной проверки оригинала, аккаунта и личности. Чужое фото само по себе не меняет владельца. Recovery переносит только канонический документ и связанные талоны/ожидание/уведомления, отзывает все сессии прежнего аккаунта и сохраняет seats/claims. Replacement добавляет неизменяемую ревизию стабильного document_id; уже выданный талон хранит document_revision. Старые fingerprints резервируются навсегда в истории. Гонки подтверждения/решения/действий прежнего владельца сериализованы. Две уже зарегистрированные канонические записи автоматически не объединяются.

Этап 2а: service_episodes и миграция 0003 для повторов завершённого талона в тот же день. Первичный Ticket остаётся COMPLETED; его поля первого обслуживания не меняются, кроме версии для обновления UI. У эпизода собственные состояние/время/сверка/версия/причина/автор. Создание только admin, переходы staff/admin своего отделения. Повтор не выделяет место/claim/номер талона; CONSUMED/SPENT сохраняются при любом его результате. Общая блокировка дня защищает занятость окна между tickets и episodes. В UI есть рабочий повтор, история и отметка на табло/в кабинете. Остаток повторов виден и на прошлые дни. Отмена сотрудником требует причины и версии. T04 реализована.

Этап 1 доводки, 15.10.2026: добавлены call_attempts/last_called_at и миграция 0002. Два вызова с паузой 120 секунд после каждого, сброс сверки при новом цикле. Есть серверные состояния рабочего дня, сводка, исторический остаток, перенос сотрудником с причиной и сохранением владельца. ENFORCE_HOURS=true блокирует новые вызовы/сверку/start/return вне 08:00–14:00; complete для начатого приёма доступен после закрытия. Ручное закрытие требует причины и идемпотентно. Развёрнуто вместе с 2а/2б на homelab 16.10.2026.

В backend/app: models, domain, main API, documents, worker, seed, config, security. Миграция 0001 содержит замороженный SQL, не вызывает create_all. PostgreSQL 16; независимые сессии запросов и worker. React в frontend/src, TypeScript, Vite, адаптивный интерфейс, QR-код без паспортных реквизитов.

Поддержан один office podgorica, service residence, окна 1–3. На день 100 seats. Дневной claim — строка document/date; дополнительный будущий лимит проверяется по активным талонам и предложениям под блокировкой документа. Отдельной service_claims-таблицы и applicants-таблицы в этой версии нет.

OfficeDay блокируется с populate_existing: иначе ORM-кэш может оставить старый next_number даже после получения блокировки. Вместимость учитывает HELD/ALLOCATED/CONSUMED. Создание талона, отмена, перенос, staff-переходы и лист ожидания имеют идемпотентность. После неявки освободить неиспользованное место может admin; claim старого документа остаётся SPENT.

При наличии WAITING новые обычные записи уступают листу ожидания. Worker резервирует предложение. Кандидат с конфликтующим глобальным ограничением получает INELIGIBLE и не блокирует остальных навсегда. Принятие предложения и истечение защищены общими блокировками.

## Документы и доступ

Фото нормализуется, метаданные удаляются; изображение и реквизиты шифруются Fernet. Поиск документа — keyed HMAC. В demo ключи создаёт seed в закрытом data volume; его нужно сохранять вместе с БД. Авторизованная выдача фото no-store; публичные ответы не содержат ФИО и документов.

Настоящий Tesseract и TD3 MRZ сравнивают данные, а не доказывают подлинность. Приложенный синтетический пример даёт ошибку имени и направляется на ручной разбор. Пока нет оценки качества на репрезентативном наборе разных паспортов.

Demo-роли доступны только в APP_ENV=demo. Есть OTP с одноразовым кодом и лимитами, staff password login с Argon2 и rate limit. Общий SMS webhook принимает POST {to,message}, Bearer token и для уведомлений Idempotency-Key. Реальный поставщик не выбран и доставка не проверена. События видны в кабинете; outbox имеет leases и backoff. Exactly-once SMS не обещается.

Outbox-события, относящиеся к документу, имеют document_id. При recovery активная lease блокирует смену владельца до завершения доставки; недоставленные связанные события переводятся новому владельцу, а неоднозначные старые события отменяются. Это предотвращает отправку содержательного уведомления на прежний телефон после подтверждённого восстановления.
